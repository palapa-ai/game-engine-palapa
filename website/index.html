Hardware ray tracing, inside Flutter.

A Metal-native real-time renderer for macOS. A raster G-buffer feeds hardware ray tracing, MetalFX upscales and denoises, frame interpolation fills in every other frame — and the finished picture lands in a Flutter Texture, compositing with ordinary widgets. Scene, camera and simulation stay in Dart. Swift owns Metal and nothing else.

Pipeline

Dart tick ─ camera + instance transforms
   │
   ├─ G-buffer raster        albedo · normal · roughness · motion · specular · depth
   ├─ Ray tracing (compute)  sun shadow ray + cosine-hemisphere sky rays
   ├─ MetalFX                MTLFXTemporalDenoisedScaler (macOS 26+)
   ├─ MetalFX                MTLFXFrameInterpolator — frame generation
   └─ Tonemap → BGRA IOSurface → Flutter texture

What it does

Real rays

Shadows and sky-lit indirect light come from MTLAccelerationStructure, with the instance structure rebuilt every frame — every object moves freely. Stand still and the clock holds, so the engine stops re-drawing the frame and starts refining it.

Frame generation

Renders low, finishes high: MetalFX temporal upscaling (denoised on macOS 26+) reconstructs the image, and the MetalFX frame interpolator generates every other frame outright.

Dart owns the world

Meshes, materials, cameras and per-frame transforms are plain Dart; whole scenes load from YAML. The frame composites as a Flutter Texture, so the viewport is just another widget.

Use

final engine = GameEngine();
await engine.start(width: 1600, height: 1000);
await engine.setScene(GameScene(
  meshes: [MeshDescription.plane(80, 80), MeshDescription.sphere(1)],
  instances: [
    const GameInstance(meshIndex: 0, material: GameMaterial(albedo: Vec3(0.2, 0.2, 0.2))),
    const GameInstance(meshIndex: 1, material: GameMaterial(albedo: Vec3(0.8, 0.3, 0.2))),
  ],
));  // each frame: engine.submit(GameFrame(camera: …, transforms: …))
